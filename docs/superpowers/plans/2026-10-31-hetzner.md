# SQLite, Docker en Hetzner (stap 5) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** De site draait als Docker-container op een Hetzner-VPS achter Caddy (HTTPS) op `talentenraad.be`, met SQLite als database, en elke push naar `main` plus een dagelijkse rebuild rolt automatisch uit via GitHub Actions.

**Architecture:** Next.js `output: 'standalone'` in een multi-stage image (Node 24, non-root), `content/` en de gekopieerde afbeeldingen ingebakken. SQLite-bestand op een Docker-volume (`/data/talentenraad.db`), migraties bij het opstarten. `compose.yaml` met `app` (alleen intern netwerk) en `caddy` (80/443, Let's Encrypt). GitHub Actions bouwt het image naar GHCR en rolt uit via SSH (`docker compose pull && up -d`). Server via `hcloud` met cloud-init; DNS via de Gandi LiveDNS-API.

**Tech Stack:** Drizzle (`drizzle-orm/better-sqlite3`), `better-sqlite3`, Docker, Caddy 2, GitHub Actions, `hcloud`, Gandi LiveDNS API.

**Spec:** CLAUDE.md "Revival" (Docker op kleine VPS met Caddy; SQLite via Drizzle; deploy via GitHub Actions) + "Open punten" voor stap 5. Beslissingen Tom 2026-10-31: Hetzner via zijn API-token (context `talentenraad`), meteen `talentenraad.be` (oude hosting staat al uit), mail via Gandi-mailbox, verse database (geen data-overzet), DNS via Gandi-API-token, Actions bouwt het image.

## Global Constraints

- Bezoekers merken niets aan de publieke site t.o.v. `1da9784`, behalve: cookie-/privacyteksten noemen Hetzner i.p.v. Vercel en er is geen analytics-categorie meer (Task 5).
- Database: één SQLite-bestand, pad uit `DATABASE_PATH` (default `./data/talentenraad.db` in development, `/data/talentenraad.db` in de container). Tabellen alleen: `users` (zonder `auth0_id`), `login_tokens`, `submissions`, `audit_logs`, `feedback`. De andere oude tabellen en de Postgres-migraties verdwijnen. Verse start: geen data-import.
- Ids blijven UUID-strings (`crypto.randomUUID()`), tijden als `integer` timestamps (Drizzle `mode: 'timestamp_ms'`), JSON-kolommen als `text` met `mode: 'json'`, enums als `text` met `enum`-lijst. Gedrag van de queries blijft gelijk; e-mailvergelijkingen blijven case-insensitief.
- Migraties draaien automatisch bij het starten van de app (één keer per proces), vóór het eerste verzoek.
- Container: Node 24, non-root user, `TZ=Europe/Brussels`, `NODE_ENV=production`, poort 3000 alleen op het interne compose-netwerk; Caddy is het enige wat 80/443 publiceert. Healthcheck op `GET /api/health` (200 `{ok:true}` als de DB bereikbaar is).
- Bij opstart: ontbrekende of te korte `AUTH_SECRET`, ontbrekende `SITE_URL` of `SMTP_HOST` → proces stopt met een duidelijke melding (alleen in productie).
- nodemailer: `connectionTimeout` 10 s, `socketTimeout` 20 s.
- Audit-log-opruiming: de huidige cron-logica draait bij elke opstart van de container (dagelijkse rebuild herstart hem); `vercel.json` en de cron-route verdwijnen.
- Secrets staan alleen in `/opt/talentenraad/.env` op de server (mode 600) en in GitHub Actions-secrets voor de deploy (`DEPLOY_HOST`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`). Nooit in de repo, nooit in commitberichten of logs.
- Kosten: niets aanmaken wat geld kost zonder expliciete bevestiging van Tom in het gesprek, vlak ervoor.
- Checklist per commit: `npm run lint && npm run type-check && npm run test:coverage && npm run build`; plus `docker build` voor Task 2–3. Hook, geen `--no-verify`; commits SSH-ondertekend (bij falen: gestaged laten, BLOCKED). Types: feat, fix, style, refactor, perf, test, docs, chore.
- Codestijl: 2 spaties, enkele quotes, `??`, `item => …`. Geen XO. Coverage ≥ 50%.

## Review Focus

1. **Lege database bij eerste start**: container start op een leeg volume → migraties maken de tabellen, inloggen met een `ADMIN_EMAILS`-adres werkt. Test in Task 1 (migratie op lege in-memory/tmp-DB).
2. **Herstart met bestaande data**: migraties zijn idempotent; data blijft. Test in Task 1.
3. **Gelijktijdige schrijfacties**: SQLite in WAL-modus met `busy_timeout`, zodat contactformulier en audit log tegelijk geen `SQLITE_BUSY` geven. Test in Task 1.
4. **Container zonder geldige env**: start niet en zegt waarom. Test in Task 2.
5. **Deploy mislukt halverwege** (image pull faalt): de vorige container blijft draaien. Gedrag in Task 3 (compose `pull` vóór `up`).
